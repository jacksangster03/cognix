# Cognix Roadmap

## v0.1 — Local MVP (current)

**Goal:** Prove the concept. Scoring engine works. App is useful on day one.

- [x] Dashboard with readiness score, mode, metric tiles
- [x] Daily check-in form
- [x] Training session log with ACWR and muscle coverage
- [x] Workout planner (mock calendar)
- [x] Progress trends (mock data)
- [x] Experiments (6 templates, start/stop)
- [x] Integration catalogue (roadmap documentation)
- [x] Settings
- [x] Deterministic scoring + recommendation engine
- [x] Demo mode with mock data
- [x] localStorage persistence

**Definition of done:** App runs locally. Dashboard shows a real readiness score and actionable protocol based on check-in + training history.

---

## v0.2 — Supabase and auth

**Goal:** Multi-device sync. Data persists beyond one browser.

- [ ] Supabase project with all tables (see DATA_MODEL.md)
- [ ] Row-level security on all tables
- [ ] Supabase Auth (email + password)
- [ ] Replace `src/lib/storage.ts` with Supabase client
- [ ] Login/signup pages
- [ ] Protected routes (redirect unauthenticated users)
- [ ] Vercel deployment with env vars

**Definition of done:** User can sign up, log data from two different devices, and see the same data on both.

---

## v0.3 — AI explanation layer

**Goal:** Claude explains scores in natural language. Ask Cognix chat.

- [ ] Claude API integration in `src/lib/ai/brief.ts`
- [ ] Daily brief cached in `daily_briefs` table (regenerate if >4 hours old)
- [ ] Zod schema validation on Claude output
- [ ] Fallback to deterministic text if Claude fails
- [ ] `DailyBriefCard` updated to show AI-generated text
- [ ] Ask Cognix: `/ask` route with simple conversation interface
- [ ] Weekly coach report (Sunday, summarise the week)

**Definition of done:** Dashboard shows a natural language brief generated by Claude, grounded in the deterministic scores.

---

## v0.4 — WHOOP OAuth

**Goal:** Replace mock WHOOP data with real biometric data.

- [ ] WHOOP developer app registration
- [ ] OAuth 2.0 flow: `/api/auth/whoop/connect`, `/api/auth/whoop/callback`
- [ ] Token storage (encrypted) in Supabase
- [ ] Token refresh before expiry
- [ ] On-demand sync: fetch latest cycle and sleep on dashboard load
- [ ] `whoop_cycles` table upsert
- [ ] HRV 30-day baseline calculation from stored history
- [ ] Replace mock data source with real WHOOP cycles

**Definition of done:** Dashboard shows real WHOOP recovery score, HRV vs baseline, and sleep data from the user's own device.

---

## v0.5 — Calendar and weather

**Goal:** Real workout slot planning. Hydration adjustments for Madrid heat.

- [ ] Google Calendar OAuth: read-only access to primary calendar
- [ ] Parse events into `CalendarBlock[]` (next 7 days)
- [ ] Replace mock calendar in planner with real events
- [ ] OpenWeatherMap API: one call per morning
- [ ] Temperature-adjusted hydration target (+0.5L if >28°C)
- [ ] Outdoor training flag in recommendations

**Definition of done:** Planner shows real calendar free slots. Hydration recommendation adjusts for today's temperature.

---

## v0.6 — Progress intelligence and Strava

**Goal:** Real trend analysis, body metrics, outdoor activity data.

- [ ] 30-day trend charts for all key metrics (real data, not mock)
- [ ] Supplement compliance tracking (days hit vs target per week)
- [ ] Experiment correlation engine: compare pre/post metric averages
- [ ] Body metrics log (weight, body fat %)
- [ ] Strava OAuth: import run and ride activities
- [ ] Strava suffer score as training load contribution
- [ ] Smart scale integration (Withings OAuth, optional)

**Definition of done:** Progress page shows real trends with enough history to see patterns. Experiments show pre/post comparison.

---

## v0.7 — Spotify intervention layer

**Goal:** Mode-matched playlist recommendations.

- [ ] Spotify OAuth
- [ ] Fetch user's playlists and audio features
- [ ] Map mode to playlist energy range (Push: high, Rest: low)
- [ ] Recommend playlist on dashboard based on mode
- [ ] "Play now" button (Spotify Web Playback SDK or app deep link)

**Definition of done:** Dashboard shows a playlist recommendation matched to today's mode. One tap opens it in Spotify.

---

## v0.8 — Ask Cognix conversational interface

**Goal:** Natural language conversation about your health data.

- [ ] `/ask` chat interface
- [ ] Context built from last 7 days of readiness scores, check-ins, sessions
- [ ] Questions like: "Why was my recovery low on Tuesday?" "What pattern do I see with caffeine and sleep?"
- [ ] Claude with function calling: can query Supabase for specific date ranges
- [ ] Conversation history stored per user

**Definition of done:** User can ask natural language questions about their data and receive accurate, grounded answers.
